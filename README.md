# omp-reteller

在主 agent 的原回复下方追加一份由独立模型生成的「复述版」。原回复不覆盖、不修改；主 agent 的模型不切换，复述版也不会进入主模型的下一次请求。

支持自动复述和 `/retell` 手动复述。默认关闭自动模式，避免未选定模型时产生额外请求。**关闭自动模式不等于卸载插件**：插件保持加载时，手动命令始终可用。

已在 omp **18.12.6** 验证。运行于交互 TUI 和持续运行的 RPC；单次 `omp --print` / JSON print 模式不运行自动复述。RPC 客户端应继续接收原回复之后的 `message_end` 自定义消息，而不是收到 `agent_end` 就关闭连接。

## 一键安装

前提：已安装 [omp](https://github.com/can1357/oh-my-pi)，并配置至少一个可用模型。

```sh
omp plugin install github:wsdx233/omp-reteller
```

默认安装到用户级插件目录，可在不同项目中使用。安装后重新启动 omp；无需手动克隆仓库或构建插件，使用 omp 独立二进制时也无需额外安装 Bun 或执行 `bun install`。

## 快速开始

1. 在 omp 中输入 `/retell model`，选择用于复述的模型，不会切换主 agent 的模型。
2. 让主 agent 完成一次回复，再输入 `/retell`，在原回复下方查看复述版。
3. 希望后续回复自动复述时，输入 `/retell on`；用 `/retell off` 关闭后，仍能手动触发。

模型来自 omp 已配置的模型目录，复用相应的 API key / OAuth 凭据，不另存密钥。也可通过 `/retell model provider/model-id` 直接指定；模型别名会解析并保存为确切的 provider/model。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/retell` | 手动复述当前分支最后一条完整的主 agent 回复；始终以原文为输入，不重复改写上一份复述版 |
| `/retell on` | 自动复述后续完整回复；不会立即重写已有回复 |
| `/retell off` | 关闭自动复述并取消正在进行的复述；保留手动能力 |
| `/retell model [provider/model-id]` | 指定独立模型；不带参数时打开模型选择器，不改变主模型 |
| `/retell prompt <提示词>` | 设置自定义复述风格 |
| `/retell prompt` | 清除自定义提示词，恢复内置默认风格 |
| `/retell context on` | 允许模型在必要时调用只读上下文工具，默认开启 |
| `/retell context off` | 完全移除上下文工具；只发送最终回复正文与编辑提示词（含已配置的自定义风格） |
| `/retell cancel` | 取消当前复述，不改变自动开关 |
| `/retell status` | 按需查看开关、模型、上下文权限、当前提示词和进行中状态；不常驻显示在状态栏 |
| `/retell help` | 显示帮助 |

手动 `/retell` 执行期间，输入框上方会临时显示带转圈的 `reteller 正在复述…` 工作行，并提示 `/retell cancel`；完成、失败或取消后自动移除。空闲时不显示，自动复述也不显示这行。

配置保存在**当前会话分支**的自定义状态条目中，恢复会话、分支或树导航时恢复对应配置；新会话不继承上一会话的设置。也可以指定新会话的启动默认值：

```sh
omp \
  --retell-model 'provider/model-id' \
  --retell-prompt '先给结论，用简短段落解释，避免生硬的报告口吻。' \
  --retell-auto \
  --retell-no-context
```

`--retell-auto` 默认不开，`--retell-no-context` 用于默认禁止上下文读取；省略它时，工具可用但不预读历史。`--retell-prompt` 可省略，默认不附加自定义要求。恢复的会话配置优先于这些启动默认值；已保存的提示词重置也会覆盖启动值。

## 自定义复述风格

例如，在 omp 中输入：

```text
/retell prompt 用轻松、自然的中文，像向同事解释一样，少用小标题和模板化措辞。
/retell
```

不带参数执行 `/retell prompt` 即恢复默认，不打开编辑器；仅空白参数也会重置。所有非空参数均视为自定义提示词，`reset` 不再作为重置关键字。提示词保留内部的换行、缩进和连续空格。

自定义要求作为独立的编辑指令附加在默认提示词之后，可指定风格、结构和措辞；会发送给所选复述模型，不会发给主模型。设置后对后续手动和自动复述均生效，不会立即重写已有回复；修改或重置会取消正在进行的旧复述。该配置与模型选择一样随当前会话分支保存，不是全局设置。

## 复述模型能看到什么

每次复述都是独立的模型请求，使用新的请求会话 / 缓存标识。**第一次请求的用户消息只有最终回复的 text 正文**，另附插件固定的编辑指令、已配置的自定义复述提示词，以及开启时的 `read_context` 工具定义。不会自动发送主 agent 的系统提示、开发者提示、推理块、工具调用参数、历史消息、附件或之前的复述。

`read_context` 是插件自己的工具，不注册到主 agent，也不共享主 agent 的工具集。模型必须明确选择来源和关键词：

- 来源仅限此前的用户正文、助手正文或工具结果正文；不含系统/开发者消息、思考块、图片、消息元数据和复述版。
- 每次只返回最新匹配的一条消息中的一个片段，最多 2000 个字符；关键词为空时读取该来源最近的片段。
- 每次复述最多允许 3 次工具调用尝试；没有匹配项时明确返回空结果，不改用其他来源。
- 没有文件、Shell、网络、修改文件或主会话操作工具；其他工具名即使被模型输出，也不会执行。

**开启上下文读取意味着相应的用户正文或工具结果片段可能被发送到所选模型的服务商**，其中可能包含项目敏感信息。若希望严格做到只披露最终正文，请使用 `/retell context off`。插件不会把数据发送到所选模型以外的另一个服务商；所选服务商自身的数据保留策略与工具能力不由插件控制。

## 行为与边界

- 只处理主 agent 的完整最终回复；不复述子 agent、带工具调用的中间消息、被截断或中断的回复；自动模式会跳过 omp 已知仍会继续运行或等待异步任务的结束通知。
- 原回复照常流式显示，复述在后台完成后以 Markdown 追加，标注模型和上下文读取次数。新一轮输入、切换模型配置、修改提示词、上下文权限变化、切换会话/分支、退出或显式取消会丢弃旧任务，防止迟到结果串入下一轮。
- 复述失败、输出为空或达到输出长度上限时，提示错误并保留原文，不把不完整输出冒充复述结果；不会静默切换模型或自动重试到另一模型。
- 默认提示词要求保留重要信息，删去废话、多余的防御性描写和生硬表达，可以重新组织结构；仅在指代或术语确实无法从正文理解时按需读取上下文。默认文本见 `src/retell.ts` 中的 `SYSTEM_PROMPT`。
- 每次复述以及工具往返都会产生额外的模型请求、延迟和费用。独立请求的 token / 费用不并入主 agent 的用量统计。
- 插件本身与其他 omp 扩展一样在进程内运行，不是对其他扩展或服务商代码的安全沙箱；隔离保证针对本插件主动构造并发送的消息。

## 开发与验证

```sh
git clone https://github.com/wsdx233/omp-reteller.git
cd omp-reteller
bun install --ignore-scripts
bun run check
bun test
```

在仓库根目录，可用 `omp plugin link .` 链接本地源码，或用 `omp -e .` 仅在本次运行中加载。

回归测试使用本机 HTTP SSE 提供器，覆盖请求隔离、按需上下文读取、读取禁用、调用预算、未知工具拒绝、空/截断回复和取消。另已用真实 omp 的 RPC/TUI 与模型验证手动/自动复述、配置恢复及去冗余效果；GitHub 安装命令已在隔离的用户目录实测，安装后无需 `-e` 即可自动发现并执行 `/retell status`。
